# 本地图标匹配（0.5.3，2026-10-05）

## 0.5.1 实机反馈后的修复

- 定位只要求＋和麦克风的唯一有效配对，占位文字改为可选辅助。没有识别到占位文字时，按用户截图中图标与文本区的比例确定区域和点击点。粘贴前检查可见区域的文字，识别到已有草稿则停止；空 OCR 结果允许继续。OCR 漏识别仍可能影响判断，写入后的核对失败会锁定重试。
- 旧版把整窗缩到 1500 像素宽，会把小图标一起缩小。将原始截图嵌入 2400×1800 的模拟整窗时成功复现配对丢失。保留原始像素后，2400/3600/4800×1800 三组模拟整窗测试通过。它们是合成背景测试，不是真实 Codex 窗口验收。
- 新增诊断计数：＋候选数、麦克风候选数、有效配对数，无论成功失败都报告。每类候选在去重后最多保留 24 个。测试覆盖 1/1/1、0/0/0、1/0/0；这些数量来自匹配结果，不把失败统称为“全部没有”。
- 用户原图结果为＋1、麦克风1、有效配对1；[标注图](../output/icon-match-result.png)中绿色为＋，橙色为麦克风，蓝色为推算输入区域，红色为无占位文字时备用点击点。蓝框是按截图比例估计，并非检测到的真实输入框边界。

用户提供截图 `截屏2026-10-05 11.21.19.png`，尺寸 1466 × 364。以截图左上角为原点，＋中心约 (55,284)，麦克风中心约 (1316,284)。最右蓝色图标是语音模式按钮，不是发送箭头。

## 实现

- `IconSamples.swift` 仅保存＋与麦克风两个 16 × 16 灰度模板，不包含任务文字或完整截图。提取脚本为 `scripts/vision/extract-templates.swift`。
- `IconLocator` 用 Swift/CoreGraphics 完成本地归一化相关匹配，无 Python、OpenCV、网络或大模型运行依赖。搜索窗口底部，多尺寸匹配、正反对比度、峰值去重，并同时要求左＋右麦克风、近似同一行及相近尺度。多组候选拒绝猜测。
- `VisualComposer` 用两图标的相对位置确定文字区域，若 OCR 提供占位文字则辅助细化点击点，坐标随窗口位置及截图缩放换算。＋、麦克风是图标定位依据，不匹配其他动态按钮。
- 原有 AX 路径失败时，可用视觉候选直接点击及 Command+V，不再要求 AX 暴露可编辑输入框。写入前重新截图确认窗口和空输入状态，写入后 OCR 核对可见文字（忽略换行与空白差异）。核对失败不重复粘贴、不自动发送。
- 发送前再次截图核对完整可见输入文字与目标窗口。优先操作唯一、启用且可执行的语义发送按钮；没有可用语义按钮时对原目标进程发出 Return，使用宿主键盘提交行为。没有发送箭头模板，不点击蓝色波形按钮。确认发送要求输入框清空及 AX 或 OCR 中新的输入区域外聊天文本回执；结果不确定时锁定重复操作。宿主若配置 Return 为换行，不保证自动提交。
- 系统录屏权限由已安装进程自行预检，侧栏独立显示。截图仅在内存中处理。

另通过空白图不匹配、移除麦克风后不匹配（即使仍有＋及蓝色语音按钮）、真实 Vision 占位文字辅助定位、截图像素到窗口坐标换算、无占位文字仍可定位及不一致文本拒绝检查。

## 0.5.2 提交链路验证

`./scripts/check-paste.sh` 通过 20 项粘贴/提交检查（0 跳过）及 14 项核心检查。新增真正跨进程 Return 测试，使用生产代码的 `KeyboardTransport` 向测试程序自己的父进程发送 Return，验证先前已粘贴的 Unicode 多行文本被完整提交、草稿清空。辅助进程校验父进程可执行文件与自身一致，不能把 Codex 或其他应用作为测试目标。新增视觉回执检查：草稿中的文字计数为 0，输入区域外 1/2 份文本分别计数 1/2。以上仍是隔离测试，不等同于真实宿主验收。

## 0.5.3 空输入框误判修复

用户实机回执报告 5–6 个＋、1 个麦克风及 1 组有效配对，随后空输入检查拒绝粘贴。在原始用户截图上复现：裁剪文字区域的 Vision OCR 输出 `po anything`，整图 OCR 输出 `Do anything`。生产流程改为整图识别后按坐标筛选输入区域，不加入宽泛的拼写容错白名单。回归检查确认整图上下文下空输入框检查通过；图标、缩放、模拟整窗、计数、回执检查仍通过。将点击后失败细分为窗口变化、无法重新截图、图标重新匹配失败及区域文字未通过检查，最后一种显示段数/字符数，不输出聊天正文。此修复已覆盖上传截图的可复现错误，真实宿主仍待验收。

## 0.5.6 错误落点修复

用户确认 0.5.5 曾把文字填到错误位置。两图标仍得到唯一配对，故不能把配对成功视为输入框确认。检查发现无占位文字时使用旧截图高度比例将备用点击点放在图标行较远上方；此点不适合较矮输入框。现在把备用区域收窄到图标行上方，点击点距图标顶部约 0.75 个模板高度；紧凑区域几何回归检查通过。两处 ScreenCaptureKit 截图配置均启用 `ignoreShadowsSingleWindow`（本机 SDK 文档说明忽略单窗口边框/阴影），匹配窗口时也校验宽高。复制回读兜底必须先在预测输入区域中识别到待填文字前缀，不能单凭复制结果触发发送。原图、缩放、反色、模拟整窗、计数、OCR 及新增紧凑区域检查通过，构建与签名检查通过。尚无本次错误位置的完整截图，故这两项是代码中发现并修复的定位风险，不宣称已证明唯一根因或完成真实宿主验收。
