# JustClick

为 Codex 桌面当前聊天提供可编辑的高频提示词。目标是安装一次后自动显示侧栏，点击提示词即可填入并发送。

**当前版本：0.8.0。** 已实现自动伴随侧栏、默认点击仅填入、独立一键发送按钮、80 条中英双语内置提示词和授权弹窗指引。新增用户截图提取的「＋、麦克风」本地图标匹配及不依赖 AX 输入控件的视觉填入路径。真实 Codex 端到端发送仍在验收，不能把截图/独立窗口测试通过当成投递通过。

视觉流程：固定窗口截图 → ＋和麦克风模板匹配 → 可选占位文字辅助定位、已有文字检查 → 点击文字区域并正常粘贴 → OCR 核对可见内容。侧栏报告＋、麦克风和有效配对的实际数量。两图标必须同时匹配且布局唯一，占位文字不再是定位的硬性条件；其他可变图标不参与定位。自动发送优先操作唯一可确认的发送按钮，否则在视觉核对输入内容后向原目标进程发送 Return。蓝色语音按钮不作发送按钮使用。发送结果仍须核对输入框清空及新消息回执；若宿主将 Return 配置为换行，则不会将键盘事件本身视为成功。长文本超出可见区域或 OCR 不一致时会停止发送并提示检查。侧栏分别显示辅助功能及录屏权限的进程预检结果。详见 [图标匹配验证](icon-matching.md)。

2026-10-05 当前聊天已收到测试标记，用户确认是手动粘贴并发送。复制后的手动发送已有证据，随后用户确认自动填入成功；自动发送仍待实机验收。详见 [验收记录](verification.md)。

同日根据实机反馈加入 `Do anything` 占位文字识别，以及左侧附件、右侧听写控件的组合定位规则。补丁已安装，辅助功能实际显示已授权；这些规则是否解决真实宿主定位仍待验证。


## 用户需求与验收目标

更新日期：2026-10-04（Asia/Shanghai）。本文是当前方案总览；早期阶段记录保留在 `docs/`，不代表最新推荐。

需求按优先级为：

1. 高频提示词由用户新增、修改、分组、置顶与排序，不重复输入全文。
2. 最好内置于当前 Codex 聊天；无法内置时，提供视觉和操作上接近内置的侧栏。
3. 安装一次后自动显示，之后不必发送“打开面板”、点击入口或按快捷键。
4. 点击一条提示词即可用于**当前聊天**，自动填入并发送，继续该聊天上下文。
5. 允许识别输入框和模拟鼠标键盘；若有可靠原生接口，优先使用接口。
6. 保留官方桌面 App；不把另一个自制 Codex 客户端当成无缝接入原聊天。

“自动”需要分开验证：开机启动、Codex 激活时显示、窗口移动时跟随、聊天切换后正确绑定，以及按钮点击后自动投递。实现其中一项不代表其余项成立。“自动发送”是**用户点击提示词后发送**，不是在打开面板时自动发消息。

## 结论与推荐顺序

- **官方内置、每个聊天自动展开、点击即可发送：目前没有完整已验证方案。** 官方有 MCP 面板与消息协议，但没有查到每次进入/切换聊天自动展开的公开保证。本机也尚未取得真实面板握手和同聊天消息回执。
- **接受外部伴随侧栏：优先将 JustClick 改成自动伴随 NSPanel，再实现输入框识别、填入校验和宿主发送按钮操作。** 这是工程建议，不是已完成能力。无需修改宿主内部结构，但自动投递需要辅助功能权限和本机验收。
- **必须在宿主界面内部常驻：优先评估小范围 CDP 扩展，而非把完整工作台全部装进来。** Codex Workspace Enhancer 和 Explodex 提供相关实现依据；这属于社区适配，升级维护成本更高。
- **原生 MCP 探针继续保留。** 如果实机证明侧栏入口、绑定和消息回传可靠，可将它作为内置版本；不能把它与外部 NSPanel 简单拼接成一个可调用的全局消息 API。

推荐的投递优先级是：已打开、已绑定当前聊天的 MCP App 中使用 `ui/message`；社区扩展中经验证的当前 composer 操作；最后是外部侧栏的辅助功能识别与键鼠操作。每层都有独立的适用条件。

## Codex Workspace Enhancer 两种方案评估

项目：[Codex Workspace Enhancer](https://github.com/papperrollinggery/codex-workspace-enhancer)。已阅读 README、原生架构、macOS 适配文档、右侧面板设计与部分输入框操作源码。没有安装或运行它；下表的项目功能属于源码/作者说明，本机兼容性未实测。

| 维度 | 原生 MCP 面板 | 可选 CDP 右侧工作台 |
| --- | --- | --- |
| 工作方式 | stdio MCP 返回 `ui://` 资源，由宿主承载 | 独立增强启动器启动带回环 CDP 的官方 App 实例，适配器注入侧栏 |
| 是否官方扩展机制 | 基于官方 MCP Apps；项目本身仍是第三方 | 不是官方插件槽位，属于社区 UI 适配 |
| 是否内置观感 | 在聊天内展示，最接近原生插件 | 注入增强窗口中，视觉上也能接近内置 |
| 自动显示 | 没有查到每次切换聊天自动展开的保证 | 可以设计自动挂载与恢复；现成项目声明的是可见入口/工作台，不等于所有聊天默认展开 |
| 当前聊天绑定 | 每个 thread entrypoint 是独立实例；需实测切换和消息路由 | 可读取宿主路由/标记；切换后必须使旧 iframe 与会话能力失效 |
| 提示词管理 | 现成项目重点是图片、参考素材和画布，需要新增提示词模块 | 可新增提示词模块，但现成工具动作也不是完整提示词库 |
| 填入与发送 | 该项目默认上下文交接，不自动发送；自定义按钮可研究 `ui/message` | 已读快捷操作实现调用 `prefillComposer` 并返回 `sent: false`，需要新增发送逻辑 |
| 启动方式 | 安装后让宿主加载插件，再打开 composer/面板入口 | 使用独立增强启动器；普通 Codex 窗口不会自动被等同增强窗口 |
| 本地网络 | 原生 stdio 功能不要求监听 TCP 端口 | 作者文档使用 `127.0.0.1:9231` 的 CDP 控制面 |
| 版本耦合 | 主要取决于宿主 MCP Apps 实现 | 还取决于 DOM 锚点、路由、iframe、调试启动和适配器 |
| 对本需求的判断 | 原生投递路线值得验证，但不能满足自动展开的承诺 | 自动常驻更有实现空间，但不能宣称安装即实现自动发送 |

**不能直接采用成品并宣布需求完成。** 原生项目以视觉工作区为核心；CDP 项目也明确保留用户发送动作。我们需要的是更小的“提示词栏”，至少还需补提示词管理、默认展开、当前聊天绑定、点击投递及失败反馈。

源码依据：

- [原生插件架构](https://github.com/papperrollinggery/codex-workspace-enhancer/blob/main/references/native-plugin.md)：显示模式由宿主决定，不提供任意宿主 CSS/侧栏替换的官方贡献点。
- [macOS 适配器](https://github.com/papperrollinggery/codex-workspace-enhancer/blob/main/references/macos-adapter.md)：独立增强窗口、回环 CDP、LaunchAgent，以及普通窗口与增强窗口的区别。
- [右侧工作台设计](https://github.com/papperrollinggery/codex-workspace-enhancer/blob/main/docs/superpowers/specs/2026-08-19-macos-workspace-panel-design.md)：目标是持续可见入口，且明确不自动发送消息。
- [输入框与快捷动作实现](https://github.com/papperrollinggery/codex-workspace-enhancer/blob/main/assets/runtime/enhancer/inject/conversation-preview.user.js)：`currentComposer` / `prefillComposer` / `runWorkspaceToolAction`，默认返回 `sent: false`。

| B | 内置 Skills 选择器 | `/`、`$` 或宿主选择器调用保存的指令；不需全文复制 | 适合重复工作，但需选择和提交，不是自动展开按钮栏 |

| L | Codex Workspace Enhancer 的 CDP 工作台 | 增强窗口中的侧栏、路由适配、可填入 | 接近界面目标，默认不发送，需裁剪与改造 |
| M | Explodex 自定义扩展 | 可在 composer 附近自动挂载按钮，提供 composer 文本操作 | 比完整工作台更适合小按钮栏；发送不是已验证的稳定公共 SDK，需额外适配 |
| N | Taskboard / AIYOUcodex 社区增强层 | CDP 注入看板/入口，部分带后台恢复 | 可借鉴挂载与生命周期，不是现成提示词自动发送方案 |
| O | ThreadDeck 的内部桥接与 AX 回退 | 硬件面板可控制现有任务与发送，使用未公开本地接口 | 借鉴上下文/回执校验；需要硬件，内部接口不能视为官方保证 |
| P | ChatGPT 网页侧栏扩展 / userscript | 浏览器 DOM 中可插入/提交提示词 | 面向网页，不直接覆盖本机桌面 Codex；若用户改用网页版可另评估 |

## 官方能力与不能混淆的边界

### MCP 面板和消息

[官方 UI 文档](https://developers.openai.com/plugins/build/chatgpt-ui)介绍 `ui/initialize`、`ui/message` 与能力检测。[插件扩展](https://developers.openai.com/plugins/build/extensions)提供 global、thread、file 等入口。

读取到的 [OpenAI MCP Extensions 规范](https://github.com/openai/mcp-extensions/blob/ca16cb3bc015baaa1b849082d8755bbef18770cb/docs/spec.md)中，thread entrypoint 是用户手动打开的聊天内容标签；每个聊天有独立实例。`ui.visibility` 控制工具对模型/App 的可用性，并不是“面板自动可见”的开关。显示模式协商也只能作用于已创建的 View，不能假定它负责每次聊天的创建。

`ui/message` 是运行在宿主 MCP iframe 中的桥接方法，不能由独立 NSPanel 或任意 localhost 网页直接拿来控制当前聊天。必须先建立真实宿主握手、可用消息能力和正确聊天绑定。

### 为什么 Hook 暂时不能解决自动展开

[官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)允许 `mcp_tool` Hook，且 `SessionStart` 可能在服务器就绪前执行。`SessionStart` 是会话生命周期，不等于每次用户切换聊天。

进一步读取 [CoreHookMcpExecutor 源码](https://github.com/openai/codex/blob/main/codex-rs/core/src/hook_mcp_executor.rs)：当前公开主线实现从 MCP 工具返回内容中提取文本，交给普通 Hook 输出流程，没有在这段路径转发 UI 资源用于显示。由此判断“加一个启动 Hook 调用渲染工具”缺少自动展开 GUI 的关键环节。公开主线源码不等于本机二进制的全部桌面实现，因此不能将其推广成永久不支持。

另有 [SessionStart 执行问题报告](https://github.com/openai/codex/issues/35863)和[桌面 MCP 面板路由问题报告](https://github.com/openai/codex/issues/50152)。这是特定版本的作者复现，不是本机必然失败的证明；说明验收要看实机，不能只看安装成功。

### 自制客户端不能冒充当前宿主接口

[官方 App Server](https://learn.chatgpt.com/docs/app-server)有 `thread/resume`、`turn/start`、`turn/steer` 等公开方法，适合自己的客户端。没有取得正在运行的桌面 App 所属实例与聊天绑定，就不能把另一进程中的同名/同 ID 会话当成当前 UI 的可靠投递路径。

## 自动伴随侧栏的实现与验收边界

0.4.0 已按下面的流程实现；真实宿主识别和发送还需要端到端验收。

1. 通过 `NSWorkspace` 的 App 激活通知显示/隐藏独立侧栏；无须先触发模型或发“打开面板”。当前用激活通知加 0.75 秒几何检查跟随窗口，自动显示不会激活 JustClick 抢焦点。App 激活事件没有聊天 ID，不能用它单独判定切换了哪个聊天。[Apple 通知文档](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification)
2. 使用不抢输入焦点的 NSPanel，通过辅助功能读取目标窗口位置和大小，在点击发送时扫描可访问控件。0.3.1 改为广度优先遍历，并为无文字标签的 textarea 增加下方位置与相邻发送控件的联合判断。切换到其他 App 时收起，窗口移动时更新位置。
3. 用户点击提示词后识别当前主聊天 composer；排除终端、搜索框、编辑器、侧聊和密码框。AX 结构不可用时再评估图像识别，不使用固定坐标作为唯一依据。
4. 输入框已有草稿时不静默清空。当前版本遇到草稿就暂停投递，不提供静默追加或替换。
5. 填入后读取控件或截图核对内容。发送前再次核对窗口和聊天上下文，再操作宿主明确可用的“发送/排队”控件。按钮处于“停止”状态时不按它；不固定假设 Return 总代表发送。
6. 等待新增消息或队列回执，区分“已点击”“已排队”“已发送”“无法确认”。内容消失、键盘事件派发成功，都不足以单独证明送达。
7. 发生切换、超时、失焦或投递结果未知时，不自动重复发送；允许用户查看草稿/回执后决定。

这种设计允许用户一次点击完成正常路径，不意味着跳过异常反馈。必要的 macOS 辅助功能授权属于一次配置；本项目不会自动替用户开启权限。

## 当前应用的打开与使用

已安装在 `/Users/f/Applications/JustClick.app`，构建产物为 `dist/JustClick.app` 和 `dist/JustClick.zip`。

1. 打开 JustClick，再切到 Codex；默认自动显示侧栏，不需要发送打开指令。
2. **点击提示词文字：自动填入，不发送**，并更新下方预览。
3. **点击右侧纸飞机：识别当前输入框，填入并请求发送**。也可使用下方“填入并发送”按钮。
4. “仅填入”只填入并核对内容；“复制”始终不要求辅助功能权限。

首次点击发送且未授权时，自动弹出指引，提供“打开辅助功能设置”“定位当前应用”和“稍后”。在「系统设置 → 隐私与安全性 → 辅助功能」中，添加并开启上面的固定路径。已修复同标识旧应用备份被选择器误认的问题：安装器现在将旧应用备份为 ZIP 并取消其应用注册，避免授权选中旧副本。系统里的同名旧记录可能不对应当前构建；当前进程的授权结果以侧栏实际状态为准。本机无有效正式签名身份，构建使用绑定代码哈希的临时签名；应用更新后可能需要移除旧记录并重新添加固定路径，而不是只看同名开关，本项目不会改 TCC 数据库或替用户绕过系统认证。

右上角 `+` 新增；下方“编辑”修改；右键菜单支持置顶、排序、复制、仅填入、发送和删除。更多菜单提供导入导出、恢复内置库、自动显示开关和登录时启动设置。登录项可能还需要用户在系统设置批准。

自动投递优先使用 AX，必要时通过图标定位后正常粘贴。发送前核对内容，优先操作可确认的发送按钮，否则使用 Enter。已有不同草稿、目标歧义或上下文变化时停止。结果不确定时显示提示，不再置灰锁住界面；只有新的用户点击才会重新尝试，不自动重复发送。

现有绑定由 App、窗口、输入控件及可读取的标题/heading/选中项组成，不是官方聊天 ID。两个聊天暴露相同 UI 指纹时不能提供严格 ID 级保证；新消息与草稿清空的界面证据也不是服务端回执。因此跨聊天、侧聊和运行中队列的真实测试是发布门槛。

## 内置提示词库

内置 32 条简短中文提示词，覆盖常用、开发、写作、翻译、分析、办公和数据。全部适合引用当前聊天上下文，不含需要先替换的模板变量。用户仍可编辑和删除。

调研来源为 [prompts.chat（原 Awesome ChatGPT Prompts）](https://github.com/f/prompts.chat) 的任务分类与 [OpenAI 提示词指南](https://developers.openai.com/api/docs/guides/prompt-engineering)。上游 [LICENSE](https://github.com/f/prompts.chat/blob/main/LICENSE) 明确将提示词内容/数据置于 CC0。我们重新编写了适合当前聊天使用的短中文指令，没有整库逐字导入 2169 条长角色提示词。

升级时先备份，再按 ID/名称补充缺少的条目，保留已有修改；安装标记防止下次启动恢复用户已删除的条目。要恢复删除的内置项，可手动选择“添加/恢复内置提示词”。实现见 `Sources/JustClickCore/Builtins.swift`。

## 数据

默认路径：`~/Library/Application Support/JustClick/prompts.json`。

- 提示词仅保存本机，应用不联网、不读取 Codex 的会话数据库或账号配置。
- JSON 导出用于备份，导入会先验证格式，再备份旧库并整体替换。
- 删除前也备份旧库；`prompts-backup-*.json` 可重新导入恢复。
- 读取损坏的库时保留原文件并禁用普通写入，先导入有效备份再恢复。
- 备份没有自动清理；可在“打开数据目录”中管理。
- 最多 2000 条，单条正文最多 500 KB，整个库最多 10 MB。
- 如需独立测试数据，可设置 `JUSTCLICK_DATA_DIR`，不会修改默认库。

仅需 Apple Command Line Tools 和 Swift 6。构建输出为本机架构的 `dist/JustClick.app`，采用本地 ad-hoc 签名，未做 Developer ID 公证。跨机器分发需要另行签名和公证。更新构建后，macOS 可能需要重新核对辅助功能授权；建议在固定路径使用。

## 当前应用的边界

- 当前版本是独立原生伴随菜单，没有向宿主进程注入 UI。
- 面板优先放在目标窗口外侧，没有空间时放到屏幕内侧；默认自动显示并检查窗口位置；没有跨平台版本。
- 快捷键固定为 Control + Option + P，占用冲突会显示提示，菜单栏仍可用。
- 自动填入优先使用 AX，失败时尝试图标视觉定位。识别或内容核对失败时停止，并显示具体原因；不承诺所有 App 版本都兼容。
- 窗口和输入框检查无法代替宿主的聊天 ID API。打开面板后应保持当前聊天；如果切换聊天，请重新打开面板捕获目标。
- “已填入”仅在可读取的输入框值发生相应变化时报告；其余结果明确为“已尝试”，不能据此认定已成功。

## 位置缓存

缓存绑定目标进程、窗口、窗口尺寸及聊天上下文检查。复用前仍快速截取当前窗口，比较两图标和输入区域边缘的微型像素指纹；一致则跳过完整控件扫描及图标/OCR定位，侧栏显示「位置缓存命中」。窗口/布局/主题变化或 120 秒过期会重新定位。文本核对仍会执行。离线样本中缓存验证约 0.14 ms，对比完整图标匹配约 53 ms；不代表整个填入流程耗时。
