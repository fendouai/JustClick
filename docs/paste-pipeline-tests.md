日期：2026-10-04（Asia/Shanghai）。验证范围是独立 AppKit 测试窗口与可控后端，不是正在运行的 Codex 界面。

## 本轮交付

- `JustClickPasteKit`：焦点快照 → 正常粘贴 → AX 定位恢复 → 本地 OCR 的可测试流程模块。
- `PastePipeline`：按层选择目标，核对上下文、有效性与草稿，聚焦后调用粘贴并读取结果。
- `ClipboardTransaction`：在临时粘贴后尝试恢复原剪贴板；若期间 changeCount 改变，不覆盖后来的用户复制内容。
- `LocalOCR`：Apple Vision 本地识别、置信度/位置筛选、歧义拒绝及坐标转换。
- `JustClickPasteChecks`：真实 AppKit/AX/Vision 集成检查与独立的可控故障检查。

这里的顺序需要说明：先使用有效焦点快照定位目标并正常粘贴；快照失效或聚焦失败且尚未写入时，才换 AX；AX 确实无目标时再换 OCR。已经发出粘贴、结果不明或只填入部分内容时，不能再次回退粘贴，否则可能重复输入。AX 歧义和上下文变化也会停止。

## 尚未证明的内容

- 原生集成使用 AppKit NSTextView 的 `paste` 动作，未验证真实 Codex/Electron 的跨进程 Command+V。
- AX 操作针对测试进程自己的窗口，未操作受限 Codex 宿主。
- OCR 使用测试窗口自身生成的渲染图，未申请屏幕录制权限，也未捕获实际桌面或聊天截图。
- OCR 坐标是定位提示，测试后端还检查了真实输入区域；识别占位文字本身不等于拥有可写输入框。
- 模拟后端只能证明流程控制和故障处理，不能代替真实窗口与聊天身份绑定。
- 这轮验证只到“文本正确填入”，没有把发送按钮、队列或消息到达记为通过。
- 剪贴板恢复为 changeCount 保护下的尽力恢复，不承诺跨进程所有微小时序竞争都能完全消除。
